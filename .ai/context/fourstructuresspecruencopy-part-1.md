*Мельница / Windmill + Дирижабль / Airship • RU/EN • v1*

Назначение / Purpose: подробная спецификация четырёх структур для реализации агентом в Minecraft Bedrock Add-On. Документ фиксирует согласованный геймплей, генерацию, интерьер, лут, мобов, сохранение состояния, крайние случаи и тесты.

Приоритет реализации: стабильные Bedrock Add-On API/Script API без Experiments. Если точная реализация отдельной детали недоступна через стабильный API, агент использует максимально близкую стабильную реализацию без изменения основной механики и явно документирует отклонение.

# 2. Общие правила структур / Shared Structure Rules

- Мельница, Дирижабль и Маленький город Вардена генерируются только в Overworld. Маленький Бастион генерируется только в Nether. Генерация каждой структуры в остальных измерениях запрещена.

- У каждой из четырёх структур один фиксированный шаблон. Разрешён только случайный поворот всей структуры на 0°, 90°, 180° или 270°; это не считается отдельным вариантом.

- После генерации блоки структуры являются обычными блоками мира: игрок может ломать их, перестраивать, открывать двери, разбивать окна и проникать любым ванильным способом.

- Разрушенная игроком структура не восстанавливается. Повторная загрузка чанка или рестарт сервера не регенерирует её.

- Содержимое каждого сундука определяется один раз при создании/первой инициализации структуры и сохраняется. Повторное открытие, рестарт или выгрузка чанка не обновляют лут.

- Если сундук сломан, оставшееся содержимое выпадает по обычным ванильным правилам.

- Спавнеры можно сломать. Блок спавнера не выпадает, а опыт выдаётся как при обычном ванильном разрушении спавнера.

- Спавнеры должны вести себя максимально близко к ванильным бесконечным спавнерам: активироваться при приближении игрока и допускать подавление освещением, если это соответствует доступной стабильной реализации.

- Если кандидат структуры пересекается с обнаруженной ванильной структурой, другой пользовательской структурой или защищаемым спавнером, обычная генерация кандидата отменяется. Структуры не должны разрезать друг друга.

# 3. Система лута / Shared Loot System

## 3.1. Заполнение сундука / Chest fill algorithm

1.  Для каждого сундука случайно определить 5--12 попыток заполнения.

2.  Каждая попытка выбирает максимум одну категорию лута по весам из таблицы ниже. Значения трактуются как относительные веса выбора, а не как независимые одновременные броски; это исключает выпадение нескольких категорий из одной попытки.

3.  Выбранная категория создаёт одну стопку/один предмет согласно диапазонам количества и дополнительным правилам.

4.  Повторение категорий разрешено, если ниже не указано исключение. Одинаковые стакаемые предметы могут объединяться по обычным правилам инвентаря.

5.  Золотое яблоко может успешно появиться не более одного раза в одном сундуке. Алмазы и остальные категории могут повторяться.
