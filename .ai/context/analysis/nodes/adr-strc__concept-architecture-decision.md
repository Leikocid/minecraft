# ADR — Structures are generated by script on chunk discovery, not by data-driven worldgen

**Status:** proposed (L0, v2). Needs the `strf` probe before it is accepted.

## Context
- Spec §7 prefers "шаблонные structure files/feature placement и событийную инициализацию". §2/§4.6/§5.5/§13.2/§14.2 define a per-chunk chance with no relocation, collision cancellation against vanilla and custom structures, whole-footprint checks, and idempotent one-time init (chests, guards, marker).
- C-2: stable APIs only, no Experiments. Data-driven jigsaw structures have shipped behind an experiment. They cannot be trusted as stable on 1.26.50 without a probe, and they give no script hook for one-time init (guards, loot) or for the spawn-area guarantee and the linked Airship.
- Legacy `feature_rules` + `structure_template_feature` are stable. But they cannot express "cancel on collision with a village", "whole footprint over land", "40–70 above max terrain", "search 40–100 blocks", or one-time mob spawn.
- The stable Script API has no chunk-generated event and no structure lookup (`/locate` results cannot be read back).

## Decision
1. **Discovery.** One throttled loop (≤ every 20 ticks) maps each player's position to chunk coordinates and queues chunks not yet evaluated, within a radius where the candidate footprint can be fully loaded (C-5b).
2. **Roll.** For each (dimension, chunk, structure), a deterministic roll `hash(worldSalt, dim, cx, cz, structureId) < chance`. `worldSalt` is random, created once and stored in a world dynamic property. Re-evaluation gives the same answer, so a lost "evaluated" bit cannot double-generate.
3. **Validate.** Probe the footprint with `Dimension.getTopmostBlock` / `getBlock` (land, water, lava, flatness, ceiling, collision signature). If invalid, cancel. No neighbour relocation.
4. **Place.** `world.structureManager.place(templateId, dim, origin, { rotation })` with rotation from the same seeded RNG. Placement waits until every chunk under the footprint is loaded (C-12).
5. **Init.** A post-place hook fills loot (`L0-loot`), spawns one-time mobs and writes the instance record. It runs exactly once, guarded by the registry (`L0-adr-strs`).
6. **Deviation report.** "Generation happens when a chunk is first seen by a player after the add-on is active, not during terrain generation." Consequences: trees and plants are overwritten inside the footprint, and chunks explored before install become eligible (the spec's secondary scenario, allowed).

## Rejected alternatives
- **Experimental jigsaw worldgen.** Violates C-2 and §7. No one-time init hook.
- **`feature_rules` placement + script init on first player proximity.** Rules like collision, altitude and land-footprint cannot be expressed, so structures would cut through villages (§2 violation). Init would also need detection of already-placed templates by scanning, which is heavy and ambiguous.
- **Scanning all loaded chunks periodically.** Forbidden by §7 and C-5.

## Consequences
- `strf` owns the queue, the tick budget (`system.runJob`), and the heuristic collision detector (signature blocks: villages, temples, mineshafts, strongholds, ancient cities, bastions/fortresses, trial chambers, and any `mob_spawner` / `trial_spawner`).
- The heuristic is incomplete by nature. That limitation must be written in the deviation report (§7 last bullet).
