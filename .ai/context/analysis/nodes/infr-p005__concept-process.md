# Process: Structure template compilation & packing (`scripts/build-structures.mjs`)

**Links:** `part_of: ["L0-infr"]` · `is_a: ["process"]` · `relates_to: ["L0-adr-tmpl", "L0-infr-p001"]`

## Purpose
Turn the four structures' checked-in layout sources into shippable `.mcstructure` NBT and get them into the release archive without a Windows editor or an in-game export step [C-8; `L0-adr-tmpl`].

## Steps
1. **Read layout sources** — per-structure TS/JSON builder definitions: block palette plus block-entity data (chest positions, `mob_spawner` + `EntityIdentifier`, shrieker `can_summon`, door half-state, wheat `growth`, rotated-stair states). Source path not yet fixed by an ADR (`L0-infr-as05`).
2. **Compile to NBT** — write little-endian `.mcstructure` for each of the 4 structures into `packs/behavior/structures/andrew/`.
3. **Round-trip unit test** — re-read each generated file and assert the exact counts the spec fixes per structure (chests/floor, spawners, shriekers, doors, footprint bounds) — a `build`-channel check, run in Node, no Docker.
4. **Hand off to packaging** — `scripts/build.mjs`'s existing zip step (`L0-infr-p001`) already includes `packs/behavior/structures/` because it zips the whole `packs/behavior` directory; no separate packaging step is needed.

## Trigger
Runs as a new step inside `npm run build`, before `validatePacks()` (a template error aborts the build the same way a validation error does).

## Failure modes
A layout source whose own generated block-entity counts don't match its source definition (e.g. wrong chest count) → round-trip test fails, build aborts, `dist/andrew.mcaddon` is not rewritten.

## Invariant
`.mcstructure` files under `packs/behavior/structures/andrew/` are always regenerated by this script; hand-editing them is forbidden — see `L0-infr-r007`.
