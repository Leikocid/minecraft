# 8. Cooldown и UI

- Cooldown способности: ровно 30 секунд после успешного создания ловушки.

- При удержании Web Sword игрок должен видеть оставшееся время cooldown через actionbar или ближайший стабильный эквивалент.

- Когда cooldown закончился, способность снова доступна.

- Если в будущем одновременно используются легендарные предметы в обеих руках: готовая способность main hand имеет приоритет; если main-hand способность на cooldown, может сработать готовая off-hand способность.

# 9. Multiplayer

- Способность должна вычисляться серверной логикой, чтобы все игроки видели одинаковый результат.

- Два игрока не должны иметь возможность обойти one-per-world crafting из-за одновременного крафта.

- При одновременной активации несколькими игроками каждый успешный вызов обрабатывается независимо.

- Паутина после создания является общей частью мира и взаимодействует со всеми игроками/мобами по обычным правилам Minecraft.

# 10. Локализация / Localization

- Русское имя: «Паутинный меч».

- Английское имя: "Web Sword".

- Все пользовательские сообщения, включая first-craft announcement и cooldown-текст, должны иметь RU/EN варианты.

- Использовать стандартную систему локализации Resource Pack, а не жёстко вшивать только один язык в скрипт.

# 11. Техническая архитектура / Technical Architecture

- Behavior Pack: item definition, recipe, Script API logic, cooldown, targeting, protected-block filtering, persistence и death-retention.

- Resource Pack: название предмета, локализация и собственная иконка/текстура при необходимости.

- Предпочтение: stable Bedrock APIs. Не использовать Preview/Beta API, если механика реализуема стабильным способом.

- Targeting и размещение 3×3×3 должны выполняться серверно. Не делать постоянный глобальный скан мира каждый tick.

- Persistent one-per-world state хранить в устойчивом world-level состоянии, доступном после рестартов.

- Любая реализация должна быть безопасной для dedicated multiplayer server.

# 12. Edge Cases

- Цель за пределами reach: ничего не происходит, cooldown не тратится.

- Луч упирается в ближайший доступный блок: использовать фактически доступную целевую точку; не атаковать сквозь стены.

- Часть 3×3×3 пересекает bedrock/контейнер: защищённые клетки пропускаются.

- Игрок активирует способность у края загруженной области: не форсировать опасную запись в незагруженные чанки.

- Игрок выходит сразу после активации: уже созданная паутина остаётся; cooldown должен сохраняться настолько, насколько это требуется общей системой cooldown проекта.

- Смерть во время cooldown не должна создавать копию меча или сбрасывать persistent one-per-world flag.

# 13. Acceptance Tests / Приёмочные тесты

- Web Sword виден в Creative Equipment, общем каталоге/search и выдаётся через /give.

- Рецепт точно соответствует 4 Cobweb + Diamond Sword.

- Первый survival-крафт успешен и объявляется в чате; второй survival-крафт в том же мире заблокирован.

- После рестарта мира второй survival-крафт всё ещё заблокирован.

- Меч не теряет прочность после длительного использования.

- Обычный melee-урон соответствует Diamond Sword и не создаёт паутину.

- Use по валидной цели создаёт приблизительно полный 3×3×3 куб Cobweb вокруг центра.

- Use вне reach ничего не создаёт и не запускает cooldown.

- После успешной способности повторное использование заблокировано 30 секунд.

- Контейнер/bedrock внутри объёма не уничтожается; допустимые соседние клетки заполняются.

- После смерти владельца Web Sword не остаётся дропом на земле и возвращается без дюпа.

- Два клиента в multiplayer видят одинаковую паутину и одинаковое состояние мира.

# 14. Готовность первой версии / Definition of Done

- Оружие импортируется без content/dependency errors на выбранной стабильной версии Bedrock.

- Все acceptance tests выше проходят в одиночном мире и минимум в тесте с двумя игроками.

- Нет известных способов дюпа через крафт, смерть или reconnect.

- Нет обязательной зависимости от Experiments/Preview.

- После прохождения тестов Web Sword можно считать самостоятельным готовым модулем и переходить к следующему оружию.

# 15. Оценка разработки / Estimate

Для отдельного Web Sword: ориентировочно 2--5 часов на первый рабочий прототип и 4--10 часов на нормально протестированный самостоятельный модуль, если AI-агент может быстро запускать Bedrock и получать runtime/content logs. Больше всего времени займут one-per-world persistence, death-retention/anti-dup и multiplayer edge cases.
