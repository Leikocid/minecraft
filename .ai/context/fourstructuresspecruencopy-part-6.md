# 7. Производительность и техническая стратегия / Performance & implementation strategy

- Предпочитать шаблонные structure files/feature placement и событийную инициализацию вместо постоянного сканирования мира каждый тик.

- Не выполнять глобальные частые поиски по всем загруженным чанкам. Генерационные проверки должны происходить только в моменты, необходимые для worldgen/инициализации.

- Стартовый поиск возле спавна выполняется один раз и сохраняет результат.

- Проверку связанных Дирижаблей выполнять один раз после успешной генерации конкретной Мельницы.

- Для определения пересечений использовать доступные стабильные средства; если стабильный API не позволяет надёжно распознавать все ванильные структуры, агент должен реализовать наиболее безопасную доступную эвристику и описать ограничение.

- Не включать Experiments только ради косметической точности.

# 9. Крайние случаи / Edge Cases

- Стартовый спавн находится рядом с океаном: искать сушу в 5×5, затем расширять до 500 блоков; при наличии сухой позиции форсировать подготовку поверхности.

- Рельеф очень неровный: обычная Мельница отменяется; стартовая может выровнять поверхность и мягко состыковать края с ландшафтом.

- Под стартовой Мельницей глубокая пещера: не засыпать её целиком; укрепить только поверхностные пустоты, необходимые для опоры.

- Кандидат пересекает деревню/храм/другую структуру/спавнер: не разрушать их. Обычный кандидат отменить; стартовая Мельница ищет следующую позицию.

- Дирижабль над рекой/океаном: кандидат отклонить, если footprint не является сухопутным.

- Гора слишком высокая для 40-блочного зазора и world ceiling: кандидат Дирижабля отклонить.

- Связанный Дирижабль не помещается нигде в 40--100 блоках: не создавать его.

- Игрок убил часть из 10 полевых Zombie Villagers и перезапустил сервер: убитые не возвращаются.

- Игрок вылечил полевого Zombie Villager: он остаётся обычным Villager и не должен снова превращаться в специального охранника из-за логики структуры.

- Игрок разграбил сундук и перезапустил сервер: лут не восстанавливается.

- Игрок сломал спавнер: он не восстанавливается.

- Два независимых Дирижабля могут быть близко, но не должны физически накладываться.

# 10. Приёмочные тесты / Acceptance Tests

## 10.1. Мельница / Windmill

14. Создать новый тестовый сервер/мир с Add-On. Подтвердить наличие одной стартовой Мельницы: сначала в зоне 5×5 чанков, либо дальше, но не более 500 блоков при необходимости поиска.

15. Проверить размер/образ: \~15×15×30, участок \~35×35, 4 лопасти, деревянная дверь спереди, 3 этажа, рабочая лестница.

16. Проверить 25 сундуков: 5 на 1-м, 8 на 2-м, 12 на 3-м; все доступны без обязательного разрушения блоков.

17. Проверить 3 спавнера по этажам и типам; верхний Vindicator получает железный топор.

18. Проверить, что слабое освещение не отключает спавнерные зоны.

19. Проверить 10 полевых Zombie Villagers: создаются один раз, не горят на солнце, не деспавнятся, не восстанавливаются после смерти, лечатся ванильным способом.

20. Проверить поля: в основном зрелая пшеница, вода, дорожки, заброшенные проплешины, старый забор с проходами.

21. Проверить лианы/паутину и отсутствие блокировки основного маршрута.

22. Разграбить/сломать сундук и спавнер, перезапустить сервер; убедиться, что состояние не восстановилось.

23. Сгенерировать достаточное число новых чанков и статистически подтвердить работу обычного 1% кандидата только на подходящей суше (без требования точного совпадения на малой выборке).

## 10.2. Дирижабль / Airship

24. Проверить фиксированный современный внешний вид: серый/светло-серый бетон, целые окна, без паутины/лиан, декоративный верхний овал.

25. Проверить габарит \~15×7×10--12 и случайные повороты 0/90/180/270.

26. Проверить две двери на противоположных сторонах и отсутствие подъёма с земли.

27. Проверить интерьер: центральный коридор + 4 комнаты; по одной лампе в каждой комнате.

28. Проверить 10 сундуков: 2×4 комнаты + 2 в коридоре.
